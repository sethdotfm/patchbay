Patchbay v2

A hard-edged, near-black CSS system for dense signal-routing and device-control UIs. Square corners, 1px rims, hard offset shadows, one accent. Every example below is live, and its markup is under it.

Reduced motion is on: pulses and stripes are still, spinners keep turning.

Five states
ok, warn, error, info, idle — always with text or an icon, never colour alone.

pb-btn--commit and pb-state-commit. Green pb-btn--ok finishes a job.
Tokens only
No raw colours, sizes or radii in components. Page CSS is layout.

Colour

Every colour token is a light-dark() pair, so the theme follows the OS unless <html data-theme> forces one. Hues are defined once as --pb-hue-* primitives; components only read the semantic tokens.

Scaling

Sizes are rem, so the whole interface follows the root font size. Use the 100 / 125 / 150% buttons in the toolbar to see this page rescale, then do the same in your app with one line. Hairlines (borders, rims, bars) stay px so they stay crisp.

html { font-size: 125%; }  /* a control room read from across the room */

Do not use zoom, and never combine it with a root font size: it scales twice. @media breakpoints in rem follow the browser's initial font size, not html's.

Tooltips

data-pb-tip on a button or wrapper, shown on hover and keyboard focus. The text is decoration: give the trigger its own name, or aria-describedby. pb-tip--top|start|end move it. pb-tip is a script-placed tip for truncated text.

Toasts

Transient feedback, bottom right. The stack is aria-live="polite"; an error toast is role="alert" and stays until dismissed. New toasts slide in with --pb-motion-enter, which is zero under reduced motion.
